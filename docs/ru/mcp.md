# MCP-сервер

`@perfscale/mcp` — это сервер [Model Context Protocol](https://modelcontextprotocol.io),
который предоставляет CLI perfscale AI-агентам (Claude Code, Claude
Desktop и любому другому MCP-клиенту). Агент может создавать YAML тестов с
валидацией записей по схеме, запускать нагрузочные тесты и читать структурированные
метрики — без доступа к shell.

Исходный код: [Perfscale/mcp](https://github.com/Perfscale/mcp). Для облачной
платформы (машины, запуски, дашборды на perfscale.su/.ru) см. сервер
`@perfscale/controlplane-mcp` в том же репозитории.

## Установка

Требуется бинарный файл `perfscale`, доступный в `PATH` (можно переопределить через `PERFSCALE_BIN`), и
Node.js 20+.

```json
{
  "mcpServers": {
    "perfscale": {
      "command": "npx",
      "args": ["-y", "@perfscale/mcp"]
    }
  }
}
```

С Claude Code:

```sh
claude mcp add perfscale -- npx -y @perfscale/mcp
```

## Инструменты

| Инструмент | Что делает |
|---|---|
| `run_test` | Запускает тест k6/locust/native (`perfscale run`), возвращает код выхода + разобранный [экспорт сводки](cli/commands.md#summary-export) |
| `lint` | Валидирует YAML-файлы (`perfscale lint`), включая проверки опечаток и идентификаторов действий |
| `get_schema` | JSON Schema для YAML `test` или `config` (`perfscale schema`) |
| `parse_summary` | Разбирает сырой k6-совместимый вывод в структурированные метрики |
| `list_actions` | Каталог встроенных действий шагов `std/*` |
| `list_configs` | Рекурсивно перечисляет YAML-файлы в каталоге, классифицируя их как test/config |
| `read_config` | Читает один YAML-файл с определением его типа |
| `write_test` | Создаёт/перезаписывает определение теста, затем проверяет его по схеме теста |
| `write_config` | Создаёт/перезаписывает конфигурацию запуска, затем проверяет её по схеме конфигурации |
| `update_config` | Перезаписывает только существующий файл (завершается ошибкой при его отсутствии), затем проверяет |
| `remove_config` | Удаляет YAML-файл теста/конфигурации |

Каждая запись сразу проходит валидацию — агент видит нарушения схемы в
том же результате инструмента, поэтому некорректный YAML никогда не попадает
на диск незамеченным.

## Переменные окружения

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `PERFSCALE_BIN` | `perfscale` | Путь к бинарному файлу perfscale |

## Примечания

- `get_schema` требует сборку perfscale с подкомандой `schema` — выполните
  `perfscale self-update`, если видите ошибку с её упоминанием.
- `run_test` выполняется локально с той же семантикой, что и
  [`perfscale run`](cli/commands.md#perfscale-run): ровно один вариант из
  k6/locust/файл, а для нативных тестов требуется конфигурация.
